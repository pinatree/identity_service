# Identity Service — API

Сервис-счётчик с авторизацией по **bearer-токенам**. Все ответы — JSON.

## Общее

- **Базовый URL:** `http://localhost:8080` (порт берётся из конфигурации, см. [config.md](./config.md))
- **Формат ответа:** единая JSON-обёртка `{ "data": ..., "error": ..., "meta": ... }`
  - `data` — полезная нагрузка (строка, число или объект); при ошибке отсутствует;
  - `error` — текст ошибки; при успехе поле отсутствует;
  - `meta` — служебные поля (`action`, `expires_in`, `allowed_methods`, ...).
- Ошибки выражаются HTTP-кодами: `400`, `401`, `404`, `405`, `409`, `500`.

## Аутентификация

1. Получите токен: `POST /api/token`.
2. Отправляйте его в заголовке каждого защищённого запроса:

```
Authorization: Bearer <token>
```

Токен хранится **в оперативной памяти** — после перезапуска сервиса все
токены становятся недействительными. Время жизни настраивается полем
`token_ttl` (секунды); по умолчанию — **300 секунд (5 минут)**.
Если токен отсутствует, неверен или истёк — ответ `401 Unauthorized`.

## Эндпоинты

### Публичные (авторизация не требуется)

| Метод | Путь               | Описание                          |
|-------|--------------------|-----------------------------------|
| GET   | `/health`          | Проверка живости сервиса          |
| GET   | `/version`         | Версия сервиса                    |
| POST  | `/api/token`       | Выпуск нового токена              |
| POST  | `/api/registration`| Регистрация нового пользователя   |
| POST  | `/api/login`       | Вход по логину и паролю (пара токенов) |

### Защищённые (нужен заголовок `Authorization: Bearer <token>`)

| Метод | Путь       | Описание                |
|-------|------------|-------------------------|
| GET   | `/counter` | Текущее значение счётчика |
| POST  | `/counter` | Увеличить счётчик на 1   |
| POST  | `/api/pass_reset` | Смена пароля (по сессии) |

## Примеры

### Проверка живости

```http
GET /health
```

```json
// 200 OK
{
  "data": { "status": "healthy", "service": "identity-service" }
}
```

### Версия сервиса

```http
GET /version
```

```json
// 200 OK
{
  "data": { "version": "1.0.0" }
}
```

Значение `version` — из конфигурации (`config.json` → переменная `VERSION` →
версия сборки по умолчанию).

### Выпуск токена

```http
POST /api/token
```

```json
// 200 OK
{
  "data": "5f24f1013dd6fba764bd3b4bfc9a06e22e9a51e8a0d3141d2215697be03bdadd",
  "meta": {
    "type": "bearer",
    "ttl": "5m0s",
    "expires_at": "2026-10-06T08:55:01Z",
    "expires_in": 300
  }
}
```

| Поле              | Назначение                            |
|-------------------|---------------------------------------|
| `data`            | Сам токен — подставляется в заголовок |
| `meta.ttl`        | Срок жизни токена (из `token_ttl`)    |
| `meta.expires_at` | Момент истечения (UTC)                |
| `meta.expires_in` | Секунд до истечения                   |

### Регистрация пользователя

Создаёт нового пользователя. Пароль не хранится в открытом виде: в памяти
сервиса остаётся только **argon2id-хеш** с отдельной случайной солью.

```http
POST /api/registration
Content-Type: application/json

{
  "login": "alice",
  "password": "secret123"
}
```

```json
// 201 Created
{
  "data": {
    "id": 1,
    "login": "alice",
    "created_at": "2026-10-09T12:00:00Z",
    "updated_at": "2026-10-09T12:00:00Z"
  },
  "meta": { "registered": true }
}
```

| Код  | Ситуация                                                        | `error`                                   |
|------|-----------------------------------------------------------------|-------------------------------------------|
| `201`| Пользователь создан                                             | —                                         |
| `400`| Невалидный JSON или логин/пароль не проходят проверку формата   | `Некорректный JSON-запрос` / `Данные для регистрации не соответствуют формату` |
| `409`| Логин уже занят                                                 | `Логин уже существует`                    |

Правила валидации:
- логин — от **3 до 20** символов (ведущие/замыкающие пробелы игнорируются);
- пароль — **не менее 5** символов.

### Вход в систему

Проверяет логин и пароль пользователя; при успехе выдаёт пару токенов —
**access** (для авторизации запросов) и **refresh** (для продления сессии).
В памяти сервиса хранится сессия с **хешами** обоих токенов, а не сами токены.

```http
POST /api/login
Content-Type: application/json

{
  "login": "alice",
  "password": "secret123"
}
```

```json
// 200 OK
{
  "data": {
    "access_token": "lK8s9fG4F0...",
    "refresh_token": "7Qp2xZvN1m...",
    "token_type": "bearer",
    "expires_at": "2026-10-09T12:05:00Z"
  },
  "meta": { "expires_in": 300 }
}
```

| Поле                  | Назначение                                    |
|-----------------------|-----------------------------------------------|
| `data.access_token`   | Токен для `Authorization: Bearer <token>`     |
| `data.refresh_token`  | Токен для продления сессии                    |
| `data.token_type`     | Тип токена (`bearer`)                         |
| `data.expires_at`     | Момент истечения access-токена (UTC)          |
| `meta.expires_in`     | Секунд до истечения (из `token_ttl`)          |

| Код  | Ситуация                                    | `error`                            |
|------|---------------------------------------------|------------------------------------|
| `200`| Учётные данные верны, токены выпущены       | —                                  |
| `400`| Невалидный JSON или пустые логин/пароль     | `Некорректный JSON-запрос` / `Логин и пароль обязательны` |
| `401`| Пользователь не найден или пароль неверен   | `Неверный логин или пароль`        |

> Пользователь не найден и неверный пароль отвечают одинаково (`401`
> с одним сообщением): раскрытие существования логина облегчило бы подбор.

### Смена пароля

Меняет пароль **владельца сессии**: пользователь определяется по bearer-токену
из заголовка `Authorization` (хеш токена ищется среди активных сессий).
Чужие учётные записи этот эндпоинт не затрагивает.

```http
POST /api/pass_reset
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "old_password": "secret123",
  "new_password": "newsecret456"
}
```

```json
// 200 OK
{
  "data": { "login": "alice" },
  "meta": { "password_changed": true }
}
```

| Код  | Ситуация                                                    | `error`                                          |
|------|-------------------------------------------------------------|--------------------------------------------------|
| `200`| Пароль сменён                                               | —                                                |
| `400`| Невалидный JSON, пустые пароли или короткий новый пароль    | `Некорректный JSON-запрос` / `Старый и новый пароль обязательны` / `Новый пароль не соответствует формату` |
| `401`| Нет/недействителен токен, сессия не найдена, старый пароль неверен | `unauthorized: ...` / `Неверный старый пароль`   |

> Сессии после смены пароля **не затрагиваются**: пользователь продолжает
> работать со своими токенами. В будущем, возможно, появится конфигурация,
> определяющая — дропать ли при смене пароля все сессии, только другие
> сессии или не трогать их вовсе.


```json

```


```json

```

## Ошибки

| HTTP-код | Значение                                          |
|----------|---------------------------------------------------|
| `400`    | Невалидный запрос: битый JSON, некорректный формат логина/пароля |
| `401`    | Нет токена, токен неверный или истёк              |
| `404`    | Путь не существует                                |
| `405`    | Метод не поддерживается для пути (см. `meta.allowed_methods`) |
| `409`    | Конфликт: логин уже занят (регистрация)           |
| `500`    | Внутренняя ошибка сервера (например, сбой генератора токенов) |

Примеры:

```json
// 401 Unauthorized
{ "error": "unauthorized: missing, invalid or expired token" }

// 404 Not Found
{ "error": "not found" }

// 405 Method Not Allowed
{ "error": "method not allowed", "meta": { "allowed_methods": ["GET"] } }
```

## Быстрый старт (curl)

```bash
# 1. Проверка живости
curl http://localhost:8080/health

# 2. Получение токена
TOKEN=$(curl -s -X POST http://localhost:8080/api/token | jq -r .data)

# 3. Регистрация пользователя
curl -s -X POST http://localhost:8080/api/registration \
  -H "Content-Type: application/json" \
  -d '{"login":"alice","password":"secret123"}'

# 3b. Вход в систему (пара токенов: access + refresh)
curl -s -X POST http://localhost:8080/api/login \
  -H "Content-Type: application/json" \
  -d '{"login":"alice","password":"secret123"}'

# 3c. Смена пароля (пользователь определяется по сессии из заголовка)
ACCESS=$(curl -s -X POST http://localhost:8080/api/login \
  -H "Content-Type: application/json" \
  -d '{"login":"alice","password":"secret123"}' | jq -r .data.access_token)
curl -s -X POST http://localhost:8080/api/pass_reset \
  -H "Authorization: Bearer $ACCESS" \
  -H "Content-Type: application/json" \
  -d '{"old_password":"secret123","new_password":"newsecret456"}'

# 4. Защищённые запросы
curl -s http://localhost:8080/counter -H "Authorization: Bearer $TOKEN"
curl -s -X POST http://localhost:8080/counter -H "Authorization: Bearer $TOKEN"
```

> `jq` нужен для разбора JSON. Без него токен можно вытащить вручную из поля `data`.
